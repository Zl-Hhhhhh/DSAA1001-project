## 1. 要完成什么

沿用 Assi1 的数据准备、EDA 和建模计划，补上模型训练、评估和预测。最终需要：

- **最终 Notebook**：修订后的 EDA、训练与评估、结论和局限，以及约一页面向市卫生主管的分析简报。
- **predictions.csv**：为老师提供的每条测试记录生成 0 或 1 的预测。
- **配套仓库**：保存输入、代码、配置和依赖说明，离线 Run All 能生成分析及预测文件。

本组固定使用 2026-10-12 下载的快照，实际检查日期为 **2016-01-04 至 2026-10-09**。课程允许的历史截止日是 10 月 30 日，但现有数据不包含 10 月 10-30 日的记录。不再从门户补充历史，也不查询隐藏测试期结果。

## 3. 每个人具体做什么

### A：数据与特征

1. 确认数据版本，检查缺失值、重复 ID、许可证和店铺匹配，保留没有 Pass/Fail 判断的历史访问。
2. 提供基础特征：业务类型、风险类别、检查目的、ZIP、月份、星期和经纬度。
3. 提供历史特征：此前检查次数、有判断次数、失败比例和最近结果。处理没有历史、同日结果不一致等情况，并比较“许可证”与“许可证加地址”两种店铺匹配方式。
4. 检查历史计算是否用了未来信息，支持没有 Results、Violations 的老师测试输入。修订相关 EDA，解释特征为什么值得测试。

建议负责：`scripts/ass2_features.py`、`tests/test_ass2_features.py`，以及字段说明。

**交接标准：** B、C 能按说明运行；每行特征保留对应 ID；同日、未来或评估批次自身的结果不会进入历史。无判断记录可以增加访问次数，但不能当作 Pass 计入失败比例。

### B：模型与实验

1. 跑通始终预测 non-Fail 的对照规则和 Logistic Regression 基线。若课程提供官方基线，再复现比较。
2. 在训练流程中处理缺失值、类别编码和数值缩放。每次只用对应训练数据学习这些规则，包括稀有类别处理。
3. 按下表做对比，记录配置、每个时间验证折的 Macro-F1、平均分和运行时间。具体参数范围沿用 Assi1 建模计划。
4. 选定特征和模型后，用 2025 验证集选阈值，范围为 0.10 至 0.80，步长 0.05。保存最终配置，再用截至 2025 年的数据重新训练，交给 C 做本地测试。

| 实验 | 内容 | 要检查什么 |
|---|---|---|
| E0 | 始终预测 non-Fail | 简单对照的分数 |
| E1 | 基础特征 + Logistic Regression | 基本信息的预测能力 |
| E2 | E1 + 历史特征 | 历史是否带来稳定提升 |
| E3 | E2 + 检查目的与历史的交互 | 历史的作用是否随检查类型变化 |

“交互”是让模型区分：同样一次历史失败，对不同检查类型可能有不同含义。额外比较树模型属于有余力再做的工作。

建议负责：`scripts/ass2_train.py`、`config/assessment2.json`、`reports/assessment2/experiments.csv`。

**交接标准：** 配置中写明数据版本、特征、处理规则、模型参数、阈值和随机种子。实验能复现，选择理由有结果支持；不根据本地测试分数调模型。

### C：评估与整合

1. 提前写好评分和预测导出代码，用验证结果及少量格式测试数据检查流程。
2. 收到锁定配置后，执行一次正式本地测试，报告 Macro-F1、两类各自的 precision（精确率）、recall（召回率）、F1 和混淆矩阵。
3. 分析已知店铺、未见店铺和不同检查类型的表现，注明样本量。解释漏报、误报及数据局限。
4. 整合 A、B 的结果和说明，写约一页分析简报；收到老师输入后生成正式预测，完成离线复现检查和展示安排。

“已知店铺”指在评估期开始前有过历史记录的店铺，即使此前没有 Pass/Fail 判断也算。漏报是实际 Fail 却预测为非 Fail；误报则相反。

建议负责：`scripts/ass2_evaluate.py`、`scripts/ass2_predict.py`、`notebooks/02_assessment2_final.ipynb`、评估图表和 `outputs/predictions.csv`。

**交接标准：** 指标按 ID 对齐计算；Notebook 和正式预测可从保存的输入离线生成。提交文件名为 `predictions.csv`，展示材料覆盖三人的工作。

## 4. 三人共用的规则

### 时间划分

| 用途 | 时间 | 使用方式 |
|---|---|---|
| 训练 | 2016-2024 年 | 学习处理规则、训练模型、比较方案 |
| 验证 | 2025 年 | 检查选定方案、选择阈值 |
| 本地测试 | 2026 年 1-9 月 | 特征、参数和阈值固定后，做正式评估 |
| 最终训练 | 2016-01-04 至 2026-10-09（现有快照） | 本地评估完成后，按固定方案用全部现有历史重新训练 |
| 隐藏测试 | 2026-10-31 至 2026-11-27 | 仅使用老师提供的检查前输入预测 |

训练内按时间验证三次：截至 2021 年训练、2022 年验证；截至 2022 年训练、2023 年验证；截至 2023 年训练、2024 年验证。所有方案使用相同划分，随机种子为 1001。

### 特征与交接

- **训练历史**只用该检查日期之前的记录；同日结果互相不可见。**验证和测试历史**只用整个批次开始前可获得的结果。
- 当前 Results、Violations、Violations 缺失标记及全时期访问总数不得作预测输入。
- A 交付特征表、标签和辅助信息，三者通过 Inspection ID 对应。辅助信息包含日期与店铺键，不能直接全部加入模型。
- B 交付完整的处理与模型流程，并输出各 ID 对应的 Fail 概率；C 使用固定阈值生成 0、1 标签。
- 老师输入没有标签时也必须能运行。收到文件后，A 核对字段，B 检查模型兼容性，C 检查预测格式。
- 本地测试后不依据分数继续调整。若发现代码错误，应记录修复和重跑原因，并说明测试结果已被查看。

结果解释要说明：重复店铺可能出现在训练和评估中；长批次冻结的历史比 28 天隐藏测试更旧；事后保存的快照不能完全还原过去的数据发布状态。
